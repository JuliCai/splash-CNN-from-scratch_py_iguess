Lab 1

Paint a picture, slide a filter

A filter is a tiny 3 × 3 grid of weights. Put it on a patch of the image, multiply the numbers that line up and add them all: that's one output square. Slide over one step and do it again.

Convolution

Warm squares are positive, cool squares are negative.

Max‑pool keeps the loudest number

Click a number to raise it · shift‑click to lower it

Each 2 × 2 window keeps only its biggest number. The picture gets half as wide and half as tall.

Lab 2

A tensor is memory plus a layout

A 3 × 32 × 32 image is stored as 3,072 numbers in one row. NVIDIA's CuTe library finds things in that row with two lists: a shape (how many steps each way) and a stride (how far one step jumps in memory). The image is (3,32,32):(1024,32,1), and pixel (c, y, x) sits at c·1024 + y·32 + x.

Layout builder

Change the shape and stride · point at a cell to see the math

Like Python and PyTorch, this lab's default strides are row‑major. Real CuTe defaults to column‑major and counts the first direction first. The shape:stride idea is the same.

Lab 4

How a network learns

The network's last layer gives ten scores, one per meme. Softmax turns them into probabilities, and the loss measures how surprised the network was by the right answer. Training nudges the weights to make that loss smaller, with step sizes set by the learning rate.

From scores to a guess

Drag the scores · pick the right answer

loss = −log(probability of the right answer)

A blind guess gives every meme 10% and costs ln 10 ≈ 2.30. The gradient of this loss is just the probabilities minus 1 for the right answer, which tells every score which way to move.

How big should each step be?

Cosine annealing takes big steps early to explore and tiny steps at the end to settle in. It's the schedule this lab uses, and the same formula as in cudagrad.

Lab 5

Back propagation, one neuron at a time

To learn, every weight needs to know: if I grow a little, does the loss go up or down? Back propagation answers that for all 62,006 weights at once, by walking backwards through the network and multiplying slopes together (the chain rule). Here it is on a single neuron.

Bonus labs

Making it faster

Batching averages what the network learns from many images and updates the weights once. In pure Python that only buys 1.2×, because every multiply still costs the same. On a graphics card it is what keeps thousands of cores busy. It also makes some of LeNet's sums enormous:

matrix multiply (batch of 128)answersproducts added per answer
conv1, forward602,11275
conv1, weight gradient450100,352
conv2, forward204,800150
conv2, weight gradient2,40012,800
fc1, forward15,360400
fc1, weight gradient48,000128

Only 450 answers, each a sum of 100,352 products. A graphics card that gives each answer one worker leaves almost all of its cores idle. In cudagrad, a CUDA autograd engine, these gradient kernels took 95% of the GPU's time.

Split‑K: cut the long sum into slices

Drag the slider

Measured in Bonus lab B, spreading the work over CPU cores. The outline shows a perfect speed‑up.

1 core1.0×
2 cores1.9×
4 cores3.0×
8 cores4.2×

Why not 8×? Some work can't be split: sending the weights out, collecting the pieces, adding them up. That part sets the limit (Amdahl's law).

Get set up before class

  1. Get the class folder from your teacher. It has src/ (the lab) and data/ (the memes) side by side.

  2. Check you have Python 3.12 or newer. Older versions work, just slower.

    python3 --version

  3. Install Jupyter. VS Code with its Jupyter extension works too.

    python3 -m pip install notebook

  4. Open the lab from inside the class folder.

    cd src && jupyter notebook lab.ipynb

  5. Run cells with Shift + Enter. Write your code in the ✏️ TODO cells and run the check under each one. Stuck? Put this in the cell and run it twice:
